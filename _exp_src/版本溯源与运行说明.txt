本包中的核心求解程序为：solve_lrp_mixed_fleet_three_scenarios.py

它不是最初上传的 solve_lrp_ga.py 原文件，也不是第三方公开仓库下载的程序。根据项目对话记录（《ChatGPT-继续对话-20261030-1736.md》）：

2. 2026-10-30 13:37之后，围绕原有解码器、路径优化和三情景设置进行了算法审查与方案调整。
3. 2026-10-30 16:24，用户明确要求开始按“有限混合车队”重算。随后将主算例设为8辆燃油车+25辆新能源车，并设置5F+28N、12F+21N两组车队结构敏感性方案。
4. 随后的程序构建阶段，明确将S1/S2设置为同一固定基准路线在无限行/日间限行矩阵下的配对评价；S3采用有限车队约束、候选中心启用位串与门店排列编码、遗传算法及有向2-opt。
5. 2026-10-30约17:14的对话中，已输出本程序及三种车队配置的完整重算包、结果汇总Excel和结果口径说明。

因此，本包对应的是上述“混合车队三情景重算版”，核心文件名为 solve_lrp_mixed_fleet_three_scenarios.py。不能将其与早期 solve_lrp_ga.py 混为同一版本。

二、程序配置（以包内 run_metadata.json 为准）

- 门店数：568；节点数：574。
- 主算例车队：8辆燃油车+25辆新能源车（均为算例假设，不是企业实测车队）。
- 车队敏感性：5F+28N、12F+21N。
- GA种群规模：20；最大进化代数：30。
- S3随机种子：20261023、20262032、20263041。
- 燃油车载重5.0 t、固定成本280元/次、单位里程成本1.28元/km。
- 新能源车载重4.5 t、固定成本230元/次、单位里程成本0.30元/km、单路径里程上限300 km。
- 每辆车每天最多执行一条配送路线。
- 候选中心日启用成本：1000元/日（另有200元/日敏感性实验）。

三、包内内容

- solve_lrp_mixed_fleet_three_scenarios.py：核心求解程序。
- 5F_28N_完整结果包.zip、8F_25N_完整结果包.zip、12F_21N_完整结果包.zip：三种车队结构的输入快照、输出明细、路线分配、可行性核验、运行元数据和运行脚本。

四、运行方式

1. 解压本包。
2. 分别解压需要复现的车队结果包（例如8F_25N_完整结果包.zip）。
3. 按该结果包内 README_运行与论文使用说明.txt 操作。输入文件位于其 input/ 目录。
4. 安装依赖：pip install numpy pandas openpyxl matplotlib
5. 运行：python solve_lrp_mixed_fleet_three_scenarios.py --input-dir input --output-dir results

注意：如需逐项复现某一历史结果，应使用该子包内保存的 input_snapshot、run_metadata.json、代码和输出记录；不要在没有核对输入快照及环境的情况下将重新运行结果直接视为历史输出。

五、学术使用边界

- 144.447 t/日需求为模拟输入，不是企业订单记录。
- 8F+25N等车队规模是算例假设，不是企业真实车队调查结果。
- 道路限行矩阵是基于现有路网数据处理形成的近似矩阵，不等同于官方逐路段法律GIS边界。
- S1/S2为固定构造基准路线的配对评价，不是企业真实历史路线。
- S3为遗传算法与有向2-opt得到的启发式可行解，不构成全局最优证明。
- 200元/日设施成本属于敏感性假设，不是企业真实设施租赁/运营成本。
